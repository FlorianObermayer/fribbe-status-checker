## Context

See `proposal.md` — Why. The assessment's remediation bundle was generated against the
current revision (`25384c0`), and each of its nine executable patches applies cleanly
(`git apply --check` verified for the combined patch and every per-finding patch). The
bundle also documents the reasoning, counterevidence and residual gaps for each fix. No main
specs exist in `openspec/specs/` yet, so this change establishes the first capabilities.

Constraints that shape the approach:

- The deployment is a single uvicorn process, so blocking work on the event loop stalls the
  whole service. Any synchronous delivery must be dispatched to a worker thread.
- Push subscription is intentionally unauthenticated (browsers subscribe without a
  session), so abuse control must be a destination restriction plus a store bound plus a
  request timeout — not an authentication requirement.
- Existing tests pin some behaviour (for example the status endpoint's readable
  `last_error` contract), so fixes must preserve those contracts where the bundle did.
- `pyright` strict and `ruff` ALL are enforced with a 120-character line length.

## Goals / Non-Goals

**Goals:**

- Close the high-severity blocking-push DoS and the medium SSRF, store-growth, redirect,
  session-revocation, notification-read, input-bounding and error-disclosure findings.
- Preserve all existing externally visible behaviour that is not the subject of a finding.
- Add regression tests for each fix so the defect classes cannot silently return.

**Non-Goals:**

- Closing the carried-forward items the bundle records as unresolved: the wildcard CSP
  source list, mutable third-party CI/base-image references, fork-contribution coverage,
  the DNS-rebinding residual (resolution happens again at send time), and write
  amplification at the capped store size.
- Making push subscription authenticated or rate-limited at the edge (a follow-up).
- Rewriting the persistent store layout (append-only/sharded).

## Decisions

### Apply the bundle's verified patches rather than re-deriving the fixes

The bundle's patches were generated by applying each finding's declared edits to a clean
copy and were verified end to end against the reviewed revision, including compile and test
runs. **Alternative considered:** reimplement each fix from the narrative. Rejected because
reimplementation would discard the bundle's verification evidence and risk diverging from
the exact behaviour the bundle validated.

### Destination validation by resolving the host and requiring globally routable addresses

`validate_subscription` gains a helper that rejects non-`https` schemes, missing hosts and
userinfo, resolves the host with `socket.getaddrinfo`, and requires every resolved address to
be `is_global`. **Alternative considered:** an allowlist of known push-service hostnames.
Rejected as the primary control because it would require configuration for legitimate
providers; noted as the most robust follow-up. **Alternative considered:** blocking numeric
notations ad hoc. Rejected in favour of the resolver, which normalizes all notations.

### Bounded delivery with redirects disabled, dispatched via `run_in_threadpool`

Push requests pass an explicit timeout and a shared `requests.Session` with
`max_redirects = 0`; every asynchronous entry point that reaches `send_to_topic_sync`
(the notification create/update handlers, the notification poll, the presence poll) wraps the
call in `starlette.concurrency.run_in_threadpool`. **Alternative considered:** making the
handlers synchronous so the framework runs them in its threadpool. Rejected as a larger
change to route signatures and streaming/response behaviour.

### Redirect validation by resolved origin, plus full encoding at the handler

`sanitize_url` normalizes the candidate the way a browser does (`\` → `/`, strip tab/LF/CR),
then parses `urlsplit(urljoin("http://localhost", candidate))` and requires scheme `http`
and host `localhost`, returning the normalized value. **Alternative considered:** extending
the prefix checks. Rejected because parser differentials are exactly what the finding
exploits; a resolved-origin check catches unanticipated forms. In addition, the
application-generated `/auth?next=...` redirect uses `urlencode` rather than
`quote(..., safe='/:?=&')`, so the value cannot inject a second query parameter. This
hardening is beyond the bundle's generated patch (the bundle flagged it in its remediation
text but emitted no code location); the sanitizer already neutralizes the demonstrated
off-origin outcome, and the encoder closes the parameter-injection class as defence in
depth.

### `only_active` as a keyword-only flag on `NotificationService.get`

The service keeps a single retrieval method with an additive `only_active: bool = False`
parameter applied only to the explicit-`nid-*` branch. **Alternative considered:** a separate
`get_active` method or filtering in the route. Rejected: a separate method duplicates the
filter branches, and filtering in the route would leave the data-layer behaviour
inconsistent.

### Move `httpx2` to the dev group at a patched version; add `requests` directly

The bundle recommends removing `httpx2` because "nothing imports it". That claim is
incomplete: `starlette.testclient` prefers `httpx2` and falls back to `httpx` with a
`StarletteDeprecationWarning`, which the repository's `filterwarnings = ["error"]` escalates
at conftest import — removal breaks the whole suite. The actual finding is that an
advisory-affected package is installed into the **production image** (built with
`uv sync --no-dev`). Therefore `httpx2` moves from `[project].dependencies` to the `dev`
group pinned at `>=2.12.0`: the production image no longer ships it, tests keep the
framework's supported client, and the lockfile resolves 2.13.1 (above all three advisory
ranges). **Alternative considered:** remove entirely and add a `filterwarnings` ignore.
Rejected because it forces the test client onto a deprecated, soon-to-be-removed path.
`requests` is promoted from a transitive to a direct dependency because the push fix imports
it directly.

### Scoped markdownlint ignores

The default branch already fails `markdownlint-cli2` (185 errors) because the OpenSpec CLI's
agent/prompt/skill docs use `**emphasis**` in place of headings and start with prose rather
than an H1. OpenSpec artifacts must begin with `## Purpose`/`## Why`, which also violates
MD041. Rather than reformat vendor-generated tooling docs in a security PR, the config
ignores `openspec/**`, `strix-reports/**`, `.github/agents/**`, `.github/prompts/**` and
`.github/skills/**`. **Alternative considered:** commit the `--fix` output and hand-fix the
remaining ~185 violations. Rejected as unrelated churn that would need re-fixing on every
OpenSpec CLI upgrade.

### Single-write `replace` on `PersistentList`

`EphemeralAPIKeyStore.save` uses a new `PersistentList.replace` that delegates to the
existing single-write `_set_items`, removing the observable empty intermediate state.
**Alternative considered:** holding a lock across `clear()`+`extend()`. Rejected because
readers do not take the store lock, so the lock would not close the race.

## Risks / Trade-offs

- [Private push relays are rejected] → Intentional tightening; documented in release notes
  and called out as **BREAKING** in `proposal.md`.
- [DNS rebinding residual: host resolved at validation and again at send time] → Documented
  as a known-unresolved follow-up; the redirect control closes the demonstrated variant.
- [Name resolution runs on the event loop during registration] → Bounded by resolver
  configuration; an operator-side follow-up can move it off-loop.
- [Rotating on every API-key-header request deletes the previous session record] → This is
  the intended revocation; concurrent requests presenting the same cookie may race, which is
  acceptable for opaque short-lived sessions and covered by regression tests.
- [Moving `httpx2` to the dev group changes `uv.lock`/`licenses.json`] → Regenerate both and
  re-run the repository dependency audit (`uv run security-check`) before merging, which
  reports no advisories.
- [Session invalidation and endpoint rejection are operator-visible behaviour changes] →
  Called out in the PR description and release notes.
- [Ignoring `.github/skills/**` etc. hides pre-existing markdown violations] → Intentional;
  those files are CLI-generated and re-generated on upgrade, so hand-fixing them is not
  durable.

## Migration Plan

1. Apply the fixes and regenerate `uv.lock` and `app/licenses.json`.
2. Run `uv run lint` and `uv run test` (all green, including new regression tests).
3. Deploy the image built with `uv sync --frozen`.
4. Rollback: revert the merge commit; there is no data migration, and the store cap and
   destination rules are code-level.

## Open Questions

- Whether the deployment intentionally uses a private push relay (the bundle flags this as an
  operator decision). If so, an allowlist or explicit opt-in is a follow-up.
- Whether to add edge rate limiting for the public push and status routes (out of scope here).
